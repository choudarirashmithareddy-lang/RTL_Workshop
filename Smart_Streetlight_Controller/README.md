# Smart Streetlight Controller Using Verilog HDL

## 1. Project Overview

The Smart Streetlight Controller is a sequential digital design implemented using Verilog HDL. It controls streetlight brightness according to the day/night condition and vehicle detection input.

During daytime, the light remains OFF. At night, the controller provides reduced brightness when no vehicle is detected and increases brightness when a vehicle is detected. A PWM signal is used to represent the light intensity.

The project demonstrates RTL design, functional simulation, logic synthesis, static timing analysis, and physical-design implementation using open-source EDA tools and the SkyWater SKY130 technology platform.

## 2. Objectives

- Design a sequential streetlight controller using Verilog HDL.
- Implement day/night detection and vehicle-responsive brightness control.
- Generate a PWM output to control the light intensity.
- Verify the design through testbench simulation.
- Synthesize the RTL into a standard-cell netlist.
- Explore floorplanning, placement, routing, and layout generation.
- Evaluate timing at minimum, nominal, and maximum timing corners.
- Review DRC and LVS reports generated by the physical-design flow.

## 3. Design Features

- **Day mode:** Streetlight remains OFF.
- **Night mode without vehicle detection:** Streetlight operates at reduced brightness.
- **Night mode with vehicle detection:** Streetlight operates at higher brightness.
- **Sequential control:** The controller uses a finite-state machine (FSM).
- **PWM generation:** The output represents different brightness levels.
- **Reset support:** The design includes reset-related logic.
- **Physical-design evaluation:** The flow generates layout and verification reports.

## 7. Functional Simulation

The design can be simulated using Icarus Verilog.

From the project directory, run:

```bash
iverilog -g2012 -o streetlight_sim RTL/*.v Testbench/streetlight_tb.v
vvp streetlight_sim
```

If the simulation completes, inspect the testbench output. If the testbench generates a VCD waveform, open it with GTKWave:

```bash
gtkwave streetlight.vcd
```

The waveform filename depends on the `$dumpfile` statement in the testbench.

## 8. Synthesis

Yosys is used to translate the RTL design into a gate-level netlist.

The synthesis scripts and generated netlists are stored in the `Synthesis/` directory. The Sky130-mapped netlist represents the design using cells from the selected standard-cell library.

The synthesis results can be used to examine the mapped logic and understand the relationship between RTL and standard-cell implementation.

## 9. Physical-Design Flow

The physical-design flow uses OpenLane with the SKY130 platform.

The main stages are:

1. **RTL preparation:** Provide the Verilog source files and design configuration.
2. **Synthesis:** Convert the RTL into a mapped gate-level netlist.
3. **Floorplanning:** Define the core area, aspect ratio, and I/O planning.
4. **Placement:** Arrange standard cells within the floorplan.
5. **Clock-tree synthesis:** Build the clock distribution network.
6. **Routing:** Connect the cells using available metal layers.
7. **Timing analysis:** Evaluate setup and hold timing.
8. **Physical verification:** Review DRC and LVS results.
9. **GDSII generation:** Produce the final layout database.

These stages transform a logical design into a physical layout suitable for further implementation review.

## 13. Technology and Validation Note

During the physical-design setup, a mismatch between the expected and available PDK versions was encountered, and the flow was run using the `-ignore_mismatches` option.

This is an important limitation. Although the selected run produced a GDSII layout and timing, DRC, and LVS reports, the project should be treated as an academic implementation and demonstration—not as manufacturing signoff.

For stronger validation, rerun the flow using a compatible, supported PDK version and review the resulting reports.
